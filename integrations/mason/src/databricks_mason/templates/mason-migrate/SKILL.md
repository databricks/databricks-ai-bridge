# Migrate an existing LangGraph agent to Mason

Integrate Mason so its commands work through the same integration points as the LangGraph
template. Preserve the existing graph and application contracts. Configuration alone does not
complete migration.

## Inspect the project and reference

Read `references/migration.json` for the server, bundled template version, chat-app choice,
durability setting, and optional profile. `references/template/` is a candidate project generated
from the templates shipped with the installed CLI. Use it as migration evidence, not an importable
application dependency.

Read [the shared Mason contract](references/template/MASON_CONTRACT.md), then inspect adjacent
template code for the integration points being adapted. If the chat app is enabled, also read
`references/template/CHAT_APP.md` and inspect `runtime/ui.py`. The contract owns runtime
requirements; this skill owns migration decisions.

Locate graph construction, state and reducers, model/tool wiring, persistence, invocation config,
interrupt/resume handling, HTTP serving, authentication, and tests. Identify package/import
conflicts with the reference. Explain the concrete changes, then implement them. Preserve the
agent's model, prompts, graph topology, tools, routing, and approval policy unless a change is
required and accepted.

## Explicitly handle existing state and contracts

- **Persistence and history:** Identify the current checkpointer, memory store, thread IDs,
  actor/tenant mapping, checkpoint namespaces, and pending interrupts. Switching checkpointers
  does not migrate checkpoints, transcripts, or memories. Preserve access to existing history until
  the transition is decided. Do not silently reset state, delete storage, or claim old conversations
  were migrated. Surface choices about copying history, starting new threads, or retiring storage.
- **Custom state and outputs:** Preserve fields, reducers, subgraphs, structured inputs/outputs,
  streaming events, and interrupts. The reference assumes message-oriented LangGraph events and is
  not a generic serializer. Implement explicit mappings without discarding custom results to fit
  the reference UI.
- **Identity and sessions:** Preserve authentication, actor/tenant isolation, and thread identity.
  The reference separates invocation UUIDs, application session IDs, and the routing cookie. Map
  existing IDs explicitly, including reopening sessions. Derive actor identity from the trusted
  application context; do not blindly trust a caller field or adopt a shared fallback.
- **Recovery and durability:** Distinguish Runtime Store invocation recovery from Session Store
  graph checkpoints. Resume only checkpoints belonging to the current invocation; otherwise input
  may replay. Address at-least-once side effects and retain stronger existing guarantees. Do not
  silently enable replay of non-idempotent tools.

## Implement the shared contract

Implement the command requirements in `references/template/MASON_CONTRACT.md`, using the template
as an example. Merge candidate `agent.toml`, `.mason/project.toml`, dependencies, and startup config
without overwriting existing choices. Candidate stores and durability are migration intent, not
authorization to provision resources or switch live state. Use `uv` and the bundled template's
compatible Mason dependency.

Keep framework-native execution independent of Mason request/context types. Adapt package
conflicts and preserve tool execution and approval logic. Merge run configuration without losing
callbacks, recursion limits, configurable fields, or checkpoint namespaces. Preserve existing
tracing when composing Mason tracing.

Reuse the HTTP server where feasible. Follow the contract's distinction between basic CLI launch
requirements, Mason `AgentApp` hooks, and optional chat UI mappings. Adapt the UI only when selected.
Do not copy sample tools, models, prompts, or business logic into the application.

## Verify and hand off

Run existing tests and relevant lint/type checks. Add focused offline regression tests for custom
inputs/outputs, streaming, remote and local tool wiring, store selection, actor/thread isolation,
interrupt/resume, and invocation recovery where used. Use fakes for remote services. Confirm the
configured entrypoint starts with the project's test setup.

Do not provision, deploy, make live model/tool calls, or run integration tests unless authorized.
`mason doctor` is a separate planned feature; do not implement it here.

Report changes, validation, unresolved state or client-contract decisions, and readiness for
`dev`, `tools add`, `sessions bind`, `memory bind`, tracing, `endpoint`, and `deploy`. Distinguish
local wiring from live validation. Exclude the reference snapshot from application packaging and
test discovery if the project would otherwise collect it.
